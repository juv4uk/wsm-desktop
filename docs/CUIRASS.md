# Cuirass: будувати, а не лише оцінювати

<!-- SPDX-License-Identifier: LicenseRef-Volnist -->

- Статус: **специфікацію написано, жодного прогону не було** — `NOT_RUN`
- Файл джобсету: [`etc/cuirass/wsm-desktop.scm`](../etc/cuirass/wsm-desktop.scm)
- Перевірка структури: `make check-cuirass` → `tests/test_cuirass_specification.py`

## Проблема, яку це лікує

Наш CI оцінює профілі командою `guix time-machine … system build --dry-run`. Це
доводить, що деривації **обчислюються**, і не доводить, що вони **збираються**.
Коштує це 20+ хвилин на кожен PR, і результат ніде не зберігається: наступний
прогін робить ту саму роботу заново.

Cuirass — це build farm GNU Guix. Він робить те саме обчислення, потім **будує**
деривації й віддає їх як substitutes через `guix publish`. Тобто:

- доказ стає сильнішим: «зібралося» замість «обчислилося»;
- наступні прогони не компілюють те саме вдруге.

## Що саме описано

`etc/cuirass/wsm-desktop.scm` — джобсет `wsm-free`:

| Поле | Значення | Чому так |
| --- | --- | --- |
| `inputs` | `guix` (master) + `wsm` (main) | два канали, без рухомих сторонніх |
| `build` | `'(channels wsm)` | збирати пакети каналу, а не весь Guix |
| `systems` | `x86_64-linux` | єдина система, для якої в нас є докази |
| `priority` | 1 | не конкурувати з upstream-джобсетами |

**Compatibility-профіль свідомо не входить.** Він тягне nonfree, а Free-джобсет
не має його публікувати — та сама межа, що й у `channels/free.scm`. Тест це
перевіряє: у файлі не повинно бути ні `compatibility.scm`, ні згадки nonguix.

## Як запустити (на машині з Guix)

```sh
cuirass register --specifications etc/cuirass/wsm-desktop.scm
cuirass web --host=127.0.0.1 --port=8081
```

Публікація substitutes, щоб наступні збірки не компілювали те саме:

```sh
guix publish --port=3000 --cache=/var/cache/guix/publish
# клієнтам: --substitute-urls=http://<host>:3000
```

Мінімальний робочий стенд — один ноутбук: `cuirass-service-type` плюс
`guix-publish-service-type` у системній конфігурації.

## Чого це не доводить

- **Нічого, поки не прогнано.** Специфікація без `cuirass register` — це текст.
  Саме тому файл і тест кажуть `NOT_RUN`.
- **Не доводить, що система завантажується.** Зібрана деривація `system` — це
  closure, а не запуск. Завантаження доводять QEMU-прогін і фізичне залізо.
- **Не доводить автентичності каналу.** Cuirass будує те, що йому дали; trust
  bootstrap каналу — окрема задача ([GUIX-CHANNEL.md](GUIX-CHANNEL.md)).
- **Не замінює H170 acceptance.** Жодна збірка не робить H170 сертифікованим.

## Чому не публічний Cuirass

Публічні інстанси (наприклад `ci.guix.gnu.org`, `guix.bordeaux.inria.fr`)
будують свої джобсети; додати туди сторонній канал може лише власник інстансу.
Тому власний стенд — єдиний шлях, який ми контролюємо. Це також означає, що
substitutes доступні лише тим, хто явно додав наш `--substitute-urls`.

## Межі

- Специфікація написана за документацією Cuirass, а не за власним прогоном:
  формат `specification` з `(name …)`, `(build '(channels …))`, `(channels …)`.
- Якщо формат зміниться, зламається саме `cuirass register` — і це буде видно
  одразу, а не через тиждень.
