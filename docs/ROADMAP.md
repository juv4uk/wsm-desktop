# Дорожня карта

<!-- SPDX-License-Identifier: CC-BY-SA-4.0 -->

Статуси відображають фактично перевірений стан репозиторію. Наявність документа або прикладу не означає, що функція вже працює.

Milestones нижче утворюють критичний шлях до першого preview. Дослідницькі напрямки, які його не блокують, зібрані в окремому розділі в кінці документа.

## M0 — основа репозиторію

- [x] Зафіксувати назву та незалежний статус проєкту.
- [x] Описати архітектуру Guix + Calamares.
- [x] Розділити ліцензії коду й документації.
- [x] Визначити політику optional nonfree components.
- [x] Додати базові автоматичні перевірки документації.

**Прийняття:** README, архітектура, етичні правила, рішення та перевірка внутрішніх посилань знаходяться в Git.

## M1 — порівняння системних backend-ів

- [ ] Зберегти та описати наявний локальний Nix-експеримент: версія, inputs, build і VM result.
- [ ] Перевірити NixOS-конфігурацію в disposable QEMU VM.
- [ ] Окремо перевірити channels/free.scm та systems/minimal.scm на актуальній Guix-інсталяції.
- [x] Побудувати й завантажити мінімальну Guix System у disposable QEMU VM (direct-kernel boot до `wsm-desktop login:` підтверджено; GRUB `--full-boot` ще не підтверджено).
- [ ] Порівняти update, rollback, store growth, package availability, hardware support та UX.
- [x] Прийняти ADR 0004: перший backend — GNU Guix, Nix відкладено.
- [ ] Підготувати problem register для Guix-шляху.

**Прийняття:** рішення про перший backend зафіксоване в ADR 0004; порівняння з Nix більше не блокує жодного пункту нижче.

## M2 — feasibility Calamares

- [x] Зафіксувати Calamares 3.4.2 як кандидата та описати його upstream-залежності.
- [ ] Перевірити, чи доступний Calamares і повний Qt 6 dependency closure у вибраній ревізії Guix.
- [ ] Якщо ні — дослідити окреме пакування Calamares та його Qt/KPMcore/Python залежностей.
- [ ] Перевірити, що live-середовище може запускати Calamares із необхідними привілеями.
- [ ] Зафіксувати точну версію Calamares і перелік доступних модулів.

**Прийняття:** Calamares запускається в тестовому live/VM середовищі з Python API та partition module (KPMcore); ще не виконує встановлення на фізичний диск.

## M3 — WSM deployment adapter

- [ ] Узгодити схему інсталяційного плану.
- [ ] Реалізувати перевірку файлових систем та mount points.
- [ ] Генерувати Scheme-конфігурацію з типізованих значень.
- [ ] Додати перевірку конфігурації без запису на диск.
- [ ] Реалізувати контрольований виклик Guix.
- [ ] Реалізувати безпечне передавання user/password data.
- [ ] Додати журналювання без секретів.

**Прийняття:** adapter проходить тести на валідних і навмисно некоректних планах; у тестах помилки не призводять до запису на диск.

## M4 — end-to-end у QEMU

- [ ] Зібрати live image.
- [ ] Запустити Calamares у VM.
- [ ] Встановити WSM на одноразовий віртуальний диск.
- [ ] Перевірити EFI boot.
- [ ] Перевірити користувача, мережу, звук і базове desktop-середовище.
- [ ] Перевірити перервану інсталяцію та зрозуміле відновлення.

**Прийняття:** повторюваний тест встановлення проходить у QEMU, а всі відомі обмеження задокументовані.

## M5 — профілі сумісності

- [ ] Перевірити Free-профіль без Nonguix.
- [ ] Перевірити окремий Compatibility-профіль.
- [ ] Вивести для кожного nonfree компонента точну назву, джерело та ліцензію.
- [ ] Перевірити, що відмова від nonfree компонентів не блокує Free-профіль.
- [ ] Провести апаратні тести та публікувати лише підтверджені результати.

**Прийняття:** два профілі мають окремі збірки/manifest-и, а вибір Compatibility є явним.

## M6 — перший публічний preview

- [ ] Визначити політику підпису образів.
- [ ] Публікувати checksums і build manifest.
- [ ] Документувати відомі проблеми та підтримуване обладнання.
- [ ] Провести тест встановлення на тестовому обладнанні.
- [ ] Окремо визначити межі підтримки та процедуру оновлень.

**Прийняття:** preview має відтворюваний build manifest, перевірюваний образ і чітке попередження про статус.

### Hardware Preview RC1 (2026-11-25)

- [ ] Опублікувати checksums і manifest вихідного архіву разом із релізом.
- [x] Зафіксувати автентифікований вільний channel lock (#39).
- [x] Надати однокомандну read-only перевірку на реальному залізі.
- [ ] Публікувати завантажувальний образ із перевіреним boot-маркером.
