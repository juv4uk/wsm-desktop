# Публікація Guix-пакетів і бінарного кешу

<!-- SPDX-License-Identifier: LicenseRef-Volnist -->

- Статус: **Free-публікація дозволена та виконується через CI**
- Перевірка: `make check-publication check-publish-script`
- Пов'язане: [GUIX-CHANNEL.md](GUIX-CHANNEL.md), [CUIRASS.md](CUIRASS.md)

## Три незалежні механізми

| Механізм | Призначення | Статус |
| --- | --- | --- |
| Guix-канал | вихідний код пакетів і модулів | публікується окремо; канал наразі не має підписаної інтродукції |
| Бінарний кеш | підписані NAR/narinfo для вже зібраних пакетів | Free-набір публікується окремим GitHub Release та Pages metadata |
| Автентифікація каналу | перевірка історії комітів каналу | не є передумовою для підписаного бінарного кешу |

Підпис кешу та автентифікація Git-каналу — різні механізми довіри. Кеш має
власний підписний ключ; відсутність `.guix-authorizations` означає лише те,
що канал не можна називати автентифікованим. Це не зупиняє публікацію
підписаних Free NAR-артефактів.

## Ліцензійні метадані WSM

Пакети WSM використовують власний запис `LicenseRef-Volnist`, який відповідає
заголовкам і файлу `LICENSES/LicenseRef-Volnist.txt`. Вони не заявляються як
GPL-3+ або як офіційні пакети GNU Guix. Перевірка `scripts/check_publication_readiness.py`
читає фактичні поля пакетів і відхиляє справжню невідповідність; додаткове
ручне передавання прапорця `--license-decision` не потрібне.

## Межі Free-набору для H170

Зафіксований upstream-only manifest містить 11 кореневих пакетів:

- `linux-libre`
- `mesa`
- `vulkan-loader`
- `vulkan-tools`
- `pciutils`
- `usbutils`
- `alsa-utils`
- `ethtool`
- `nvme-cli`
- `smartmontools`
- `lm-sensors`

Цей набір не включає WSM-owned `wsm-tools`, Nonguix, пропрієтарний драйвер
NVIDIA, `nvidia-firmware`, `linux-firmware` або Intel microcode. Пакет
`wsm-tools` має окремий релізний потік, власну provenance та контрольні суми.

Окремим експериментальним пакетом збирається `linux-libre-h170` із патчем
Nouveau GP107 atomic KMS. Його NAR/source-реліз не означає, що GPU завантажив
firmware, активував KMS або має 3D/compute-прискорення.

## Рішення власника та їхня сфера

ADR [0011](decisions/0011-owner-revokes-two-unapproved-gates.md) фіксує, що
процесні вимоги #586 як загальна заборона публікації та обов'язкова
автентифікація Git-каналу не були затвердженими рішеннями власника. Вони не
використовуються як гейт для Free-пакетів чи бінарного кешу. Факти залишаються
видимими у звітах, а не маскуються під успішну перевірку.

Це рішення не надає прав на сторонні пропрієтарні бінарники. Поточна
Free-публікація їх не містить; Compatibility-профіль не входить до цього
релізного набору. Для майбутнього розповсюдження стороннього firmware потрібні
права та умови відповідного правовласника — ADR власника проєкту цього не
замінює.

## H170-орієнтована локальна збірка кешу

Скрипт `scripts/publish-hardware-cache.sh` використовує явну мікроархітектуру,
а не `--tune=native`, створює GC roots, перевіряє фактичні ліцензійні
метадані, збирає пакет і запускає `guix publish` із підписним ключем.

Dry-run:

```sh
scripts/publish-hardware-cache.sh --cpu skylake --dry-run
```

Реальний запуск потребує Guix/guix-daemon і root-доступу до системного ключа:

```sh
sudo scripts/publish-hardware-cache.sh --cpu skylake
```

Поточний процес CI збирає загальний upstream Free manifest. Локальна збірка
`wsm-tools` з `--tune=skylake` є окремим варіантом для сумісної Skylake
машини; вона не замінює перевірки звичайної, нетюнінгованої збірки. Guix
tuned-builds не проганяє тести автоматично, тому цей факт виводиться скриптом.

## Перевірка та публікація

Кожен релізний потік зберігає код/lock/provenance у Git, а бінарники —
у GitHub Releases або Actions artifacts. Перед переведенням чернетки в
опублікований стан workflow повторно завантажує файли, перевіряє SHA-256,
формат NAR/tarball та атестацію там, де вона налаштована. ISO, NAR і великі
build outputs не додаються у звичайні Git-гілки.

## Чого це не доводить

- Збірка пакета доводить побудову деривації, а не завантаження на фізичному H170.
- Підписаний кеш не автентифікує Git-канал.
- Linux-libre/Nouveau candidate не доводить firmware loading, GPU binding,
  KMS, 3D/compute, suspend/resume чи роботу всіх периферійних пристроїв.
- Сумісність на фізичній GA-H170-Gaming 3 та GTX 1050 Ti потребує перевірки
  саме на цій машині.
