# ADR 0009: бекенд інсталятора лишається Python, не Rust

<!-- SPDX-License-Identifier: LicenseRef-Volnist -->

- Статус: **proposed**
- Дата: 2026-11-26
- Розглянуто: `distinst` (System76), `chwd` (CachyOS), Rust-TUI на `ratatui`

## Питання

Чи варто переписати бекенд інсталятора на Rust, взявши `distinst` або `chwd` за
основу, і зробити три морди — CLI (`clap`), TUI (`ratatui`), GUI (`iced`)?

## Що кажуть першоджерела

**`distinst`** — Rust-бібліотека для розбиття (libparted), LUKS/LVM і
завантажувача (systemd-boot або GRUB). Але модель встановлення в неї така:
розбити, **розпакувати squashfs-образ**, chroot, виконати `configure.sh`,
поставити завантажувач. [1]

Тобто це модель «розгорнути готовий образ». Guix так не ставить систему: він
**будує store на цільовому диску** (`guix system init`), а не розпаковує образ.

Це не припущення. У 2018 році автор дистрибутива на базі NixOS відкрив у
`distinst` issue #108 з проханням додати хуки, бо його процес не збігається з
«unpack + chroot». Питання закрили без реалізації. [2]

**`chwd`** — детектор заліза CachyOS: визначає гібридні GPU, ноутбуки, підтягує
драйвери й профілі живлення. Прив'язаний до Arch і pacman-хуків. [3]

**Rust-TUI** (`ratatui`) — життєздатний, але це UI-шар, а не бекенд.

## Рішення

Бекенд лишається Python. Причини, в порядку ваги:

1. **Невідповідність моделі встановлення.** `distinst` розпаковує образ; Guix
   будує store. Міст між ними — це переписати `distinst`, а не підключити його.
2. **`chwd` вирішує задачу, яку ми вже вирішили.** `wsm-hwcheck` збирає докази
   з sysfs, `profile_match.py` зіставляє їх із профілем. Різниця в мові, не в
   результаті.
3. **Немає кому супроводжувати.** Rust-бекенд без постійного мейнтейнера — це
   більший ризик, ніж Python-бекенд із 200 тестами.
4. **Три морди вже є.** `--guided`, `--tui`, модуль Calamares — і всі три
   викликають один бекенд. Мова фронтенду не є проблемою.

## Що з Rust усе-таки варто взяти

Не код, а **патерни**:

| Патерн | Звідки | Чи потрібен нам |
| --- | --- | --- |
| Розділення привілеїв: UI від користувача, демон від root | elementary installer [4] | **так**, у нас TUI працює від root цілком |
| Автоматичне зіставлення GPU → профіль драйверів | `chwd` | уже є в `profile_match.py` |
| TUI на `ratatui` | Rust-спільнота | ні, поки наш TUI без залежностей |

## Коли це рішення варто переглянути

- якщо бекенд стане вузьким місцем за швидкістю (зараз він виконує кілька
  команд `mkfs`/`mount` — швидкість не є властивістю цієї задачі);
- якщо з'явиться мейнтейнер, готовий вести Rust-шар;
- якщо Guix змінить модель встановлення на «розгортання образу».
