# ADR 0010: публікація власних пакетів каналу

<!-- SPDX-License-Identifier: LicenseRef-Volnist -->

- Статус: **прийнято** — вказівка власника, 2026-11-28
- Дата: 2026-11-28
- Пов'язане: [#367](https://github.com/juv4uk/wsm-desktop/issues/367) (ліцензія), `.github/workflows/package-archives.yml`, `.github/workflows/package-archives.yml`

## Контекст

Два конвеєри публікації були вимкнені запобіжником, який вимагав рішення власника,
закриття #367 і визначеного володіння ключем. Власник дав вказівку **двічі**:
«починай публікувати гуікс пакети під моє залізо».

Цей ADR існує тому, що рішення спершу було записане лише в заголовку workflow —
тобто знову в коді, а не в документі рішень. Власник не читає англійської і не
шукає рішень у YAML.

## Рішення

Власник, як власник ліцензії, дозволяє розповсюдження **зібраних бінарників
власного коду WSM**. Питання ліцензії (#367) закрите цією вказівкою, а не рішенням
агента.

Межі, які з цього випливають і які не можна розширювати самостійно:

1. **Публікуються лише власні пакети каналу.** Сьогодні це `wsm-tools`. Чужі
   збірки (ядро Guix, Mesa, Nonguix) не публікуються як наші.
2. **Запуск лише вручну.** Жодних тригерів на push чи тег: архів, що з'являється
   без запиту людини, — це початок обігу непідписаних бінарників.
3. **Лише чернетка релізу.** Опублікований реліз уже роздається; додавати в нього
   бінарник «після факту» — рішення, якого ніхто не ухвалював.
4. **Без ключа підпису.** Шлях `guix pack` не потребує ключа. Substitute-сервер
   лишається вимкненим, бо ключа не існує — це технічна перешкода, не політична.

## Що це не вирішує

- **Хто створює ключ підпису** і де він зберігається. Без нього substitutes
  неможливі, і агент не має права створювати ключ за власника.
- **Чи публікується ядро `linux-wsm-gp107`.** Воно дає найбільшу користь (години
  компіляції), але лежить у визначенні системи, а не в каналі, і його перенесення
  впирається в те, що Nonguix не входить у Free-набір каналів.

## Наслідки

- `package-archives.yml` лишається окремим ручним шляхом лише для власного
  `wsm-tools`: `guix pack` на pinned `channels.lock.scm`, SHA-256 та provenance,
  Actions artifact на 30 днів; прикріплення можливе лише до явно вказаного
  наявного Draft Release. Перший публічний pre-release `wsm-tools 0.1.0-rc6`
  уже зібрано й перевірено workflow run `46117970977` з вихідного commit
  `0a9865b0bdb4a22ba29d2a6625cd830ef4712e5d`; archive SHA-256:
  `c4df62eecb221bbfaac1acadfde24e431a6e0ab848b59acdc8d734f4a4400c10`.
  Це self-contained pack, не substitute cache; його release body не заявляє
  OSI/FSDG approval чи фізичну H170/GP107 acceptance.
- `substitutes.yml` — незалежний H170 Free upstream cache для фіксованого
  11-пакетного manifest. Після PR #790 він генерує ephemeral Guix key на
  кожному тимчасовому runner; private key не залишає runner, public key та
  provenance/attestation публікуються поруч із versioned NAR assets. Це не
  постійний WSM signer і не додає `wsm-tools` до upstream Free manifest.
- PR #790 усунув залежність H170 Free cache від відсутніх довгострокових
  repository secrets/variables; попередня невдала спроба не є результатом
  поточного workflow після цієї зміни.
- H170 Free та WSM-owned пакети мають різні scope й provenance. Жоден із цих
  механізмів не дозволяє включати Nonguix, proprietary NVIDIA driver,
  NVIDIA firmware або Intel microcode до Free closure.
- Автентифікований WSM channel lookup залишається окремим Phase B завданням:
  `guix pack -L .` з pinned офіційним Guix source tree не видається за
  authenticated channel consumer.
- Політичні тести перевіряють розділення каналів, межі складу пакунків і
  читабельне повідомлення про збій.
