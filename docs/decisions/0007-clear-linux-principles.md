# ADR 0007: принципи Clear Linux без Clear Linux

- Статус: **proposed — на розгляді [#147](https://github.com/juv4uk/wsm-desktop/issues/147)**
- Дата: 2026-11-26
- Канонічне завдання: [#147 — перенести перевірені принципи Clear Linux](https://github.com/juv4uk/wsm-desktop/issues/147)
- Підзадачі: [#148 — CPU ISA evidence](https://github.com/juv4uk/wsm-desktop/issues/148), [#149 — відтворювані Guix-профілі](https://github.com/juv4uk/wsm-desktop/issues/149), [#150 — stateless configuration](https://github.com/juv4uk/wsm-desktop/issues/150), [#151 — вимірюваний performance baseline](https://github.com/juv4uk/wsm-desktop/issues/151)
- Пов'язане: [ADR 0004](0004-nix-guix-backend-strategy.md) (Guix — єдиний backend), [ADR 0003](0003-free-by-default.md), [ETHICS.md](../ETHICS.md)

## Контекст

Clear Linux OS був найшвидшим дистрибутивом x86_64 «з коробки» протягом десятиліття й
залишив по собі документовані інженерні рішення, які варто вивчити.

Але **проєкт закритий**:

- 18.07.2025 Intel оголосив про припинення підтримки негайно, без перехідного періоду;
- останній реліз — 43800, 21.07.2025;
- 01.03.2026 сайт `clearlinux.org` знято з мережі;
- репозиторій на GitHub заархівовано в режимі read-only.

Тобто **жодних оновлень безпеки, жодної підтримки, жодного community handoff**. Це
визначає форму рішення: Clear Linux не може бути ні залежністю, ні джерелом коду,
ні upstream-ом, до якого ми повертаємо виправлення. Лишається єдине, що не застаріває
й не потребує супроводу — **принципи**, перевірені часом і описані публічно.

Друга межа — архітектурна. Clear Linux оптимізувався під Intel і збирався власним
`swupd`/`autospec` конвеєром. WSM має інший backend ([ADR 0004](0004-nix-guix-backend-strategy.md))
і не може дозволити собі другий пакетний менеджер.

## Рішення

Принципи поділено на три категорії. Кожен пункт — окреме рішення, а не загальна
декларація.

### Приймаємо

| Принцип Clear Linux | Як це виглядає у WSM |
| --- | --- |
| **Атомарне оновлення всієї системи з відкатом** | Guix generations дають це від природи: нова конфігурація будується до активації, попередні покоління лишаються, повернення — вибір покоління. Нічого реалізовувати не треба, треба не зламати. |
| **Мінімальна база, компоненти за явним вибором** | Профіль за замовчуванням не тягне зайвих служб. `systems/desktop.scm` уже дотримується цього: Bluetooth вимкнено, зайвих сервісів немає. |
| **Stateless-мислення: чіткий власник кожного файла** | У Guix конфігурація декларативна, а `/gnu/store` незмінний. Лишається визначити, що належить системі, що користувачеві, що генерується під час роботи й як відновлюється. Це [#150](https://github.com/juv4uk/wsm-desktop/issues/150), і це питання власності, а не технології. |
| **Вимірювання замість відчуттів** | Будь-яке твердження «швидше» супроводжується відтворюваним benchmark-ом із зафіксованими умовами. Без числа — не твердження ([#151](https://github.com/juv4uk/wsm-desktop/issues/151)). |
| **Близькість до upstream** | Свіжі ядра й інструменти без власних патчів «про всяк випадок». Патч лише за вимірюваної потреби, і за можливості — в upstream. Це вже принцип 3 у [README](../../README.md). |

### Адаптуємо з обмеженнями

| Принцип | Обмеження WSM |
| --- | --- |
| **Оптимізація під конкретний CPU** | Лише за runtime-видимими ISA-можливостями, ніколи за vendor/model. Загальна збірка лишається переносимою: жодного глобального `-march=native`. Спеціалізовані варіанти — тільки для конкретного workload з benchmark-ом і безпечним fallback ([#148](https://github.com/juv4uk/wsm-desktop/issues/148)). |
| **Profile-guided і link-time optimization** | Допустимі як опція пакета, а не як глобальний прапорець дистрибутива: PGO ламає відтворюваність, якщо профіль не зафіксований. Спершу — відтворюваність, потім швидкість. |
| **Function multi-versioning / runtime dispatch** | Тільки для бібліотек, де виграш виміряно. Диспетчеризація сама по собі додає складності й поверхні для помилок. |

### Відхиляємо

| Що | Чому |
| --- | --- |
| **`swupd`, bundles, mixer, autospec** | Другий пакетний менеджер поруч із Guix — це рівно те, що забороняє [ADR 0004](0004-nix-guix-backend-strategy.md). Атомарність і мінімалізм берімо як властивості, не як інструменти. |
| **Intel-only припущення** | WSM не має бути дистрибутивом одного виробника. x86-64 — перша ціль, не єдина. |
| **Глобальні агресивні прапорці компілятора** | `-O3 -march=native` для всієї системи дає невідтворювані збірки й падіння на іншому залізі. |
| **Телеметрія за замовчуванням** | Clear Linux мав opt-in телеметрію. WSM не має її взагалі: preflight read-only, мережа не використовується ([ETHICS.md](../ETHICS.md)). |
| **Копіювання коду або конфігурацій** | Проєкт закритий і не отримує виправлень безпеки. Будь-який скопійований файл — це борг без власника. |

## Наслідки

- **Немає нової залежності.** Рішення не додає жодного пакета, служби чи джерела.
- **Немає другого system manager.** Усе, що Clear Linux робив через `swupd`, WSM робить через Guix або не робить зовсім.
- **Порівняння з Clear Linux неможливе на практиці.** Він більше не оновлюється, тож «ми швидші/повільніші за нього» — твердження без доказової бази. Benchmark-и порівнюються з поточними дистрибутивами, а не з мертвим.
- **Кожна підзадача має власний критерій приймання.** Цей ADR не реалізує нічого сам; він фіксує, що саме зі спадщини Clear Linux береться, а що ні.

## Що може змінити це рішення

- Поява живого форку Clear Linux із підтримкою безпеки — тоді варто переглянути, чи чиїсь патчі варті перенесення.
- Доказ, що конкретна ISA-спеціалізація дає вимірюваний виграш на реальному парку WSM-користувачів.
- Зміна backend-а за [ADR 0004](0004-nix-guix-backend-strategy.md) — тоді частина «відхиляємо» переглядається разом із ним.
