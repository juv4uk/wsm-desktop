## Короткий висновок

WSM Desktop — один з найбільш дисциплінованих hardware-first Linux-проєктів у pre-alpha стадії.
Філософія «спершу обладнання + чесні докази + upstream-first + fail-closed» реалізована
послідовно і рідкісно якісно. Водночас критичний шлях до першого корисного образу
( live ISO → QEMU end-to-end install ) досі не закритий. Проєкт виглядає як дуже сильна
дослідницька лабораторія, яка чекає, коли хтось почне писати інсталятор наскрізь.

## Що вже працює

### 1. Hardware collector (`wsm_hwcheck`)

- Повністю read-only, безпечний для запуску на будь-якій системі.
- Збирає звіт через sysfs/procfs + обмежену діагностику `journalctl -k` / `dmesg`.
- Версіонована JSON-схема, чесна політика `unknown` / `not-tested`.
- 36+ тестів, CLI з `--compact` / `--output`.
- Це єдина частина репозиторію, яку можна використовувати вже сьогодні.

### 2. Guix backend adapter (половина)

- `wsm_install/backend_guix.py` + `guix_deploy.py` генерують `operating-system` declaration.
- Allow-list, типізація, dry-run, відсутність виконання користувацького Scheme.
- REALIZE / APPLY свідомо не реалізовані (безпека).
- 20+ тестів на валідні та навмисно биті плани.

### 3. Системні конфігурації

- `systems/minimal.scm`, `desktop.scm`, `live.scm`, `compatibility.scm`.
- Автентифікований `channels.lock.scm` (free-only).
- Профілі Free / Compatibility розведені.

### 4. Інфраструктура якості

- REUSE + SPDX у кожному файлі.
- Власна ліцензія ВОЛЬНІСТЬ.
- CI на Python 3.10–3.13 + реальні QEMU guest-тести.
- Мовна політика (українська канонічна) перевіряється скриптом.
- Багато ADR і чітких рішень (особливо 0001, 0003, 0004).

## Що відсутнє (критичний шлях)

| Пункт | Статус | Вплив |
|-------|--------|-------|
| Live ISO (KDE Plasma) | Відсутній | Блокує будь-яке тестування користувачем |
| Frontend інсталятора | Не обрано | Issue #10 відкрите |
| End-to-end install у QEMU | Відсутній | Немає доказу, що система взагалі встановлюється |
| Автентифікований Nonguix lock | Відсутній | Compatibility-профіль не відтворюваний |
| Фізичні hardware profiles з evidence | Майже немає | Немає реальних «підтримується» |

## Сильні сторони

1. **Дисципліна невизначеності** — код і документація відмовляються вгадувати. `_firmware_unknown()` і подібні патерни — рідкісна якість.
2. **Безпека інсталятора продумана до реалізації** — preflight, freshness, privacy, fail-closed.
3. **Юридична і provenance-гігієна** — REUSE, SPDX, чітке розмежування Free/Compatibility, ніяких прихованих ключів.
4. **Тестова культура** — тести не декоративні, є schema validation, QEMU smoke, exact-head CI.
5. **Документація як першокласний артефакт** — рішення, межі, evidence policy зафіксовані.

## Слабкі сторони / ризики

1. **Перекіс зусиль у документацію та research** (PCIe DOE/SPDM, CXL RAS, topology) замість закриття критичного шляху.
2. **Frontend інсталятора все ще в повітрі** — Calamares feasibility є, але рішення не прийнято.
3. **Compatibility-профіль** має source, але немає pinned authenticated lock → не можна назвати релізним.
4. **Трекер** містить багато AI-згенерованих issues/PRs і дублів (покращилося після REVIEW-2026-11-26, але шум лишився).
5. **Ризик «вічного pre-alpha»** — якщо не з’явиться відтворюваний `make image-live` + один успішний QEMU install, проєкт залишиться дослідницьким.

## Рекомендований порядок дій (пріоритет)

1. **Закрити live ISO** (issue #170)
   - `systems/live.scm` + `make image-live`
   - QEMU/OVMF boot до Plasma session marker
   - Manifest з exact Guix commit + SHA-256

2. **Обрати frontend інсталятора** (issue #10)
   - Або зафіксувати Calamares, або власну тонку оболонку
   - Не тягнути обидва шляхи одночасно

3. **Довести Guix handoff до кінця**
   - Реалізувати контрольований `guix system init` у disposable QEMU
   - Один повний цикл: live → partition → plan → deploy → reboot → login

4. **Автентифікований Compatibility lock** (issue #210)
   - Окремий `channels.compatibility.lock.scm`
   - Fail-closed тести, що Free не тягне Nonguix

5. **Перший реальний hardware profile**
   - Хоча б один конкретний ПК (наприклад H170 + GTX 1050 Ti з issue #171)
   - Evidence bundle з artifact hashes
