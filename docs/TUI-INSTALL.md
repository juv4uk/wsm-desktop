## Місце TUI серед трьох варіантів

Основний інсталяційний Live-сеанс пропонує три режими: **консольний CLI**, **псевдографічний TUI** та **графічний Calamares**. Цей документ описує лише другий режим.

TUI — це повноекранний текстовий інтерфейс у терміналі з рамками, підсвіченим вибором та керуванням стрілками. Він не потребує desktop, Qt, Calamares або GPU. Це не те саме, що звичайний консольний CLI: CLI використовує послідовні текстові prompt-и без повноекранного перемальовування.

## Поточна поведінка

TUI дозволяє вибрати диск і firmware mode, перевірити точний шлях цілі та отримати read-only план. Install callback відсутній. Після preview інтерфейс повідомляє, що APPLY вимкнено, команди розбиття/форматування/монтування не виконувалися, а WSM не встановлено.

Клавіші: стрілки або j/k; на українській розкладці — о/л; вихід — q/й. У полі підтвердження шляху ці символи залишаються звичайними символами назви пристрою.

## Вимоги для завершеного TUI

- Запускається як окремий пункт Installer Selector, а не як неявна заміна CLI чи Calamares.
- Проходить реальний інтерактивний smoke на ISO у BIOS та UEFI.
- Кирилиця, рамки, US/UA перемикання, backspace, Esc і навігація працюють на tty.
- Використовує спільні hardware report, typed plan і єдиний Guix backend.
- Показує ті самі перевірки цілі та підтвердження, що й CLI/Calamares.
- Не заявляє успішне встановлення, доки backend не виконав APPLY і не пройшов post-install verification.

## Поточні межі

TUI сьогодні є preview, а не робочим інсталятором. Його unit tests використовують FakeScreen і не доводять фактичне відображення у tty. Реальне APPLY має бути реалізоване в спільному backend, а не додане до TUI як окремий шлях обходу безпеки.
