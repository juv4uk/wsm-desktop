# Профілі заліза

<!-- SPDX-License-Identifier: LicenseRef-Volnist -->

Кожен перевірений пристрій — це тека `profiles/hardware/<vendor>/<model>/` з
двома файлами:

```
profiles/hardware/<vendor>/<model>/
  profile.scm      конфігурація для цієї машини
  evidence.json    посилання на звіт і перевірені функції
  artifacts/       файли, для яких evidence.json зберігає SHA-256
```

**Профіль без `evidence.json` не вважається профілем.** Це гіпотеза, і в
інсталяторі вона не бере участі.

## Чому так

Спокуса написати «має працювати» велика, і саме на ній спіткнувся не один
дистрибутив. Різниця між «ми думаємо, що ця плата заведеться» і «ми перевірили
її на фізичній машині, ось звіт, ось що не працює й що ще не перевіряли» — це
різниця між обіцянкою і фактом.

`evidence.json` зобов'язаний містити:

- `report_id` зі звіту `wsm-hwcheck` — докази посилаються на джерело;
- `verified_functions` — що саме перевірено, зі статусом `pass`, `fail` або
  `not-assessed`;
- `known_limitations` — усе, що не працює або працює частково;
- `not_assessed` — **непорожній**: жодна машина не перевірена повністю.

Шаблон — [`template.json`](template.json). Скопіюй, заміни значення, але не
залишай вигаданих.

## Перевірка

```sh
python3 scripts/check_profile_evidence.py
```

Скрипт відхиляє bundle, якщо:

- жодна функція не має статусу `pass` (усе `not-assessed` — це не доказ);
- функція зі статусом `fail` не згадана в `known_limitations`;
- у `verified_by` є електронна адреса;
- `slug` не збігається з текою, у якій лежить файл.

## Що писати в `verified_by`

`автори проєкту` або назву агента (`local agent`, `web agent`). Імена й
електронні адреси людей у репозиторії не публікуються — це правило проєкту, не
побажання.
